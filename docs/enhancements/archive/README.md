# Archived designs

The designs in this folder were built. Each is kept as it was written, with its status notes, so
the reasons behind a piece of the code can still be read; the code itself is the reference now,
with the [architecture pages](../../architecture/README.md) as the walk-throughs. A design that is
not built yet stays one level up, in [`docs/enhancements/`](..).

| Design | What it designed | What shipped, and what did not |
|---|---|---|
| [alexa-plus-operator-assistant-enhancement.md](alexa-plus-operator-assistant-enhancement.md) | The operator's assistant: a read-only MCP server, a Strands agent, the suggestion catalogue, memory, the sign-in, the ask page, two deployments. | Built in #185 to #192 and the rounds after it; [architecture/ops-mcp-agent.md](../../architecture/ops-mcp-agent.md) describes it as it runs. Not built: AgentCore Memory as a second layer, a dev seed script for a judge's briefing, reserved concurrency on the agent (the account's quota left none). |
| [alexa-plus.md](alexa-plus.md) | Alexa+ on top of the assistant: the voice on the page, OAuth discovery for account linking, the async briefing, each environment's Alexa+, what it costs. | Built in #195 to #206; [architecture/alexa-plus.md](../../architecture/alexa-plus.md). The real add-on has not been linked: Amazon's toolkit is gated and US-only (friction 10.26). |
| [ops-assistant-architecture-expert.md](ops-assistant-architecture-expert.md) | The assistant explains the architecture: the resource catalogue, `architecture`, `investigate` and `table_sample`. | Built in #204 and #208. When a resource is added under `infra/`, `lambdas/tests/test_ops_mcp_architecture.py` names what the catalogue lacks ([architecture/README.md](../../architecture/README.md)). |
| [ops-assistant-log-reader.md](ops-assistant-log-reader.md) | The assistant reads the logs: `log_review` and `api_errors`, root causes, and what using dev beside production changed. | Built in #218 to #228. Its own text says what was never timed or tried against a live account (the Logs Insights `SOURCE` units, the wake call's saving). |
| [ops-assistant-vision.md](ops-assistant-vision.md) | The assistant sees the vision pipeline: `vision_status`, `topic_findings`, the worker's log in its own Region, two rules moved from the prompt into code. | Built in #300, #307 and #313. Two limits it records still stand: only `vision_status` and `topic_findings` screen a voice caller's text, and the MCP function's 512 MB bounds how large a running state it parses. |
| [vision-evidence.md](vision-evidence.md) | The evidence lines: what the pipeline measured and decided, written as one line per event, joined by ids, and read back by `vision_evidence`. | Built as the submission round's first PR. It is still the full reference for the line kinds, their fields and the join keys. Not built: the assistant reading the evidence from the running state (the decision ring) rather than the logs. |
| [opencv-agentic-vision-enhancement.md](opencv-agentic-vision-enhancement.md) | The first vision design, reviewed against an outside strategy note: the stateless OpenCV worker beside the imagery, the diff-first adapter, the triage agent, COOL. | Built as the vision stack (#240 to #254, merged through #285). Not built: COOL as a deployed worker; the Graviton session measures it by hand ([cool-benchmark-runsheet.md](../../cool-benchmark-runsheet.md)). |
| [vision.md](vision.md) | The vision pipeline's reference: every component and setting, what was measured, what went wrong, what the operator does, and what is still open (§10). | Built and deployed on dev. Living docs still cite its tables and §10; [architecture/blogger-vision.md](../../architecture/blogger-vision.md) is the walk-through. |
| [rail-access-monitor.md](rail-access-monitor.md) | The Rail Access Monitor: the angle, the four cities, the per-PR specifications. | Built as PRs A to L, merged through #285. Where its text and the code differ, its status notes say so, and the code is right. |
| [dailysubject_hook.md](dailysubject_hook.md) | One rotating rail topic: a city a day, then a week, with the goal rotation. | Built in #331, #338 and #335. Left out by design: `measure_subject_first`, and moving the crypto feed onto the hook. |
| [supply-chain-tracker-enhancement.md](supply-chain-tracker-enhancement.md) | Counting ships at shipping choke points, the entry before the rail angle. | The `ships` task is built and tested; the choke-points topic was never seeded, and known static objects (platforms, buoys, rigs) are still counted as vessels (vision.md §10, item 20). |
| [phase-0-foundations.md](phase-0-foundations.md) | The original build spec: the repository, the two branches, the release model, the bootstrap and the first deploy. | Built. The settings it left to GitHub (a ruleset on both branches, a required reviewer on `production`) are in [configuration.md](../../configuration.md#github-repository-settings). |
| [public-repo-runsheet.md](public-repo-runsheet.md) | The GitHub settings to apply once the repository is public: rulesets, the required reviewer, secret scanning, fork approval. | The repository is public; which of its steps have been applied is the owner's to confirm, and [configuration.md](../../configuration.md#github-repository-settings) lists the settings. |
